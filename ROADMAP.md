# ImageCraft Roadmap

ImageCraft is an actively developed pre-1.0 package. The repository contains only the current public contracts, implementation, tests, retained corpus, and reproducible evidence needed to validate them.

## Current baseline

- Independent SwiftPM products: `ImageCraftCore`, `ImageCraftImageIO`, `ImageCraftPDF`, and `ImageCraftSVG`.
- iOS 15+ and macOS 12+.
- Bounded PNG/JPEG/GIF/WebP/HEIF probing and static primary-frame decoding. When the current ImageIO runtime exposes `public.avif`, the same bounded ISO-BMFF top-level-box scanner conditionally adds AVIF while retaining a distinct AVIF brand identity. The qualified AVIF still slice now includes controlled 8-bit alpha and 10-bit SDR/sRGB preserve-source inputs: source precision is explicit in `ImageProbe`, unknown precision is conservatively over-reserved, and the bounded <=4-pixel ImageIO thumbnail fallback preserves 16-bpc storage instead of quantizing it to 8-bit. WebP additionally has a bounded animated `VP8X/ANIM/ANMF` contract, while HEIF/AVIF sequence semantics remain fail-closed and separately unqualified.
- ImageIO implementation v12 keeps the earlier SDR/HDR correctness fence and qualifies narrow HEIF and AVIF HDR output profiles on macOS 14 / iOS 17+ runtimes that register the corresponding source types. Operation requests must explicitly use `.high + preserveSource`; ImageIO receives the public `DecodeToHDR` request and framework-native output is then required to remain HDR/extended-range, while legacy/default `.standard`, `.high + convertToSRGB`, SDR HEIF requested as `.high`, packed RGBA8, progressive and animation HDR paths fail closed. Direct-HDR PQ HEIC and the retained synthetic 10-bit PQ AVIF remain qualified on the current macOS and iOS 27 runtimes. v12 retains public ISO gain-map detection that Xcode 27 omits from `kCGImagePropertyAuxiliaryData`, de-duplicates them against future property-array exposure, charges their description/XMP metadata, and reserves at least 8 B/px for high-range output even when the primary SDR raster is 8-bpc. `DecodeLimits.coreV1` therefore rejects the retained gain-map HEIC by default; with `maximumAuxiliaryAttachments >= 1`, the current macOS runtime composes it to HDR at ordinary and <=4-pixel fallback sizes. The same retained file is recognized as `ISOGainMap` on the current iOS 27 simulator, but ImageIO returns sRGB/headroom=1 even for `DecodeToHDR`, so ImageCraft deliberately fails high requests closed there. The fixture is frozen by SHA-256 and `scripts/verify-hdr-ios-runtime.sh` makes the platform divergence reproducible. This does not qualify raw gain-map delivery/selection, gain-map JPEG/AVIF, tone mapping, HDR animation/progressive output, or non-`CGImage` representations.
- PDF and SVG use separate document/vector-rasterization contracts rather than pretending to be `EncodedImageFormat`. `ImageCraftPDF` qualifies only an unencrypted single-page, zero-rotation Core Graphics path with bounded encoded/page/target limits, PDF user-space page geometry, fit/fill rasterization into transparent 8-bpc sRGB premultiplied RGBA, probe/data identity checks, and conservative modeled target-surface working-set admission. Multipage, encrypted and rotated documents remain fail-closed. `ImageCraftSVG` is deliberately a strict dependency-free v1 subset over public Foundation `XMLParser` + Core Graphics: it requires `viewBox`, accepts only fill-only `svg/g/rect/circle/ellipse/path`, limits path syntax to M/L/H/V/C/S/Q/T/Z; rasterizer identity v2 computes reflected S/T controls in Double, routes both smooth families through one bounded reflection path, revalidates each reflected axis against the coordinate bound before path publication, and resets cubic/quadratic reflection state across incompatible segment families; pre-rejects DTD/entity bytes before XML parsing, and fail-closes processing instructions, script/CSS/text, external references/image/use, fonts, stroke/transform, gradients/filters/masks/clips, animation, arcs and all unknown elements/attributes/namespaces. Both products model only the target raster surfaces they own; framework-private XML/Core Graphics parser/render allocations are not claimed bounded.
- Exact-timeline GIF/APNG/WebP and pre-split JPEG-sequence preparation with on-demand frames, bounded decode windows, source reuse, cancellation, strict Codable invariants, format allowlists, APNG CRC/type/order validation, GIF interactive/text-rendering rejection, bounded WebP RIFF/ANIM/ANMF timeline validation, early frame admission, cumulative sequence metadata budgets, actual decoded-row-stride publication checks, and owned-APNG persistent semantic replay anchors that eliminate unnecessary checkpoints only when full-canvas source/background semantics prove a safe later replay start. WebP uses the generic ImageIO encoded-frame backing only after its own container validator proves canvas, frame rectangles, timing, loop, blend/disposal flags and nested VP8/VP8L dimensions; retained three-frame evidence covers subrect alpha blend plus disposal-to-background. Full-source + previous and subrect-background remain conservative controls. The owned animation implementation first shipped in `0.1.0-alpha.7` (`3b7f7ef212acfa42a022d7cd0bfad73c0cd2d252`). `0.1.0-alpha.8` (`c16a868f1a1c0ed6b1a916ad082f762969ac5a7e`) additionally publishes the bounded frame-window cost contract; Fovea `develop` now pins that exact revision and has a production `EncodedAnimationPlaybackPreparing` implementation that composes ImageCraft window estimates with host-global decode-count and working-set admission. Host adoption is therefore closed for the development line, while stable-device timing/RSS/energy/thermal qualification and release-level evidence remain open.
- Bounded progressive-JPEG sessions with monotone non-final generations, cancellation fencing, terminal reclaim after accepted-input failures, and a package-internal 500-SOS CPU-amplification ceiling shared by full-container security inspection and the incremental parser. A separate source-bound libjpeg-turbo 3.2.0 classic-API probe now proves that persistent buffered-image coefficient state can consume arbitrary 1-byte through full-file chunk schedules without replaying prior entropy: 5 cases / 21 schedules retain identical scan-completion state and final RGB, while private jmemmgr 3.2.0 checkpoints expose the dominant retained/final-render allocator live bytes without promoting that private ABI to a public contract. The same probe now observes virtual-barray controls before realization: four 1920-wide cases have an exact multi-minheight no-backing-store hinge (`threshold-1` fails before coefficient allocation; threshold succeeds byte-exact), while the 23×13 case intentionally falsifies a universal 1-byte rule because libjpeg's mandatory one-minheight fallback succeeds even with `max_memory_to_use=1`.
- Static PNG and JPEG encoding with explicit color, orientation, alpha, metadata, and output-byte policies.
- Versioned capability, resource, lifecycle, and failure contracts.
- Public API, external-consumer, retained-corpus, independent-oracle, platform, and performance gates.
- Reproducible direct-ImageIO vs ImageCraft raster-path comparison with alternating measurement order, raw samples, input identity, and exact pixel-output validation.
- Schema-6 target-derived raster probe records source decode, creation from an already-decoded surface, exact-pixel identity, byte cost, and cached-image materialization; it keeps storage-efficient format selection orthogonal to reuse/latency admission, records exact logical-live/publish/reclaim bytes for the codec-owned LZFSE paths, and leaves PNG framework-private creation transient explicitly unknown rather than relabeling it as an allocator/RSS bound; the nearest-integer aspect-fit normalization candidate is retained as a measured negative result. Static ImageIO codec implementation version 5 replaces cross-call `CGImageSource` retention with bounded pure-value prepared state and an independent aggregate prepared-store authority.
- Independent PNG qualification now provides a real non-ImageIO raster path for static full-resolution non-interlaced grayscale 1/2/4/8-bit, grayscale+alpha8, RGB8, RGBA8 and indexed 1/2/4/8-bit sources with explicit sRGB authority, plus the same grayscale 1/2/4/8-bit, grayscale+alpha8, RGB8, RGBA8 and indexed 1/2/4/8-bit source-model set in Adam7 scan order under explicit sRGB authority. The 8-bit implementation is exposed through the public opt-in `BoundedPNGDecoder` packed producer with a mandatory hard operation budget and public phase ledger; the default ImageIO backend remains unchanged. It includes indexed PLTE/tRNS, grayscale/RGB tRNS, truecolor suggested PLTE, exact packed-value conformance, explicit operation-budget admission, pure RFC1950/RFC1951, one 36 KiB streaming logical-output window that covers the full 32 KiB DEFLATE lookback plus pending delivery without a second history copy, a caller-owned cross-IDAT byte cursor with no concatenated compressed-body copy, packed-row/pass-aware unfiltering with no full inflated or per-pass surface, shared immutable validated container facts, and source-bound libpng hostile/conformance evidence. Preserve-source RGB ICC is implemented behind stricter non-interlaced unit/resource gates; non-interlaced untagged input is qualified only for an explicit `.convertToSRGB` fallback while preserving `.absent` source provenance, and still fails under `.preserveSource`; Adam7 source types/depths outside that standard RGBA8-decoder source-model set, any non-sRGB Adam7 color authority, unqualified cICP/HDR and other unrepresented color semantics fail closed. A separate high-depth seam defines orthogonal packed-format dimensions and exact straight RGBA16LE storage. The broad implementation remains package-only, while a narrow public opt-in `BoundedPNG16Decoder` / `ImagePackedRGBA16Decoding` slice now exposes only full-resolution explicit-sRGB grayscale16, grayscale+alpha16, RGB16 and RGBA16 in non-interlaced or Adam7 scan order, with grayscale/RGB tRNS and a mandatory hard operation budget; it rejects sBIT, ICC, cICP/HDR metadata, EXIF, animation, color conversion, resizing and `.high` before publication. `PNGIndependentRGBA16Decoder` itself now covers all standard non-indexed 16-bit PNG source channel models—grayscale, grayscale+alpha, RGB and RGBA—in non-interlaced and Adam7 scan order under explicit sRGB/full-resolution qualification. Gray/RGB `tRNS` comparisons stay in the complete UInt16 stored-sample domain; GA/RGBA stored alpha remains straight. The bounded inflater feeds exact 2/4/6/8-Bpp source rows and scatters or expands directly into the final RGBA16LE value without pass surfaces. Structured `sBIT` metadata preserves the actual source channel model (`gray`, `gray+alpha`, `RGB`, or `RGBA`) without rewriting stored pixels or inventing source alpha for tRNS-derived output. RGB/RGBA16 additionally implement preserve-source embedded RGB ICC with pre-inflate admission and exact profile-byte retention; pixels remain raw source-faithful RGBA16LE and profile bytes enter transfer/resource accounting. A second ICC slice now converts a generic forward-device RGB/XYZ matrix/TRC subset whose qualified profile class is either monitor (`mntr`) or input (`scnr`): both classes require a nondegenerate authored device-to-XYZ-PCS matrix and no LUT/MPE transform; monitor profiles additionally require D50 media white within s15Fixed16 quantization tolerance and colorants that reconstruct that white, while input profiles treat `wtpt` as captured-medium metadata and require only a plausible nonnegative-X/Z, positive-Y value rather than forcing device code white to D50, and either one qualified shared RGB TRC or three per-channel independently-qualified TRCs whose curveType/parametric encodings, functions and parameters may differ. Shared TRCs may be parametric type-0...type-4 whose source-domain mapping is finite, normalized, weakly nondecreasing and needs no source clipping, or `curveType` count=0 identity, count=1 positive u8Fixed8 forward gamma, or count>1 normalized weakly-nondecreasing UInt16 samples with ICC-defined uniform-domain linear interpolation. Type-0 requires positive gamma; type-1/type-2 add positive affine scale, an in-domain threshold and normalized upper endpoint; type-3/type-4 require valid breakpoint/power-base, nonnegative lower slope, near-continuity and normalized endpoints, with type-4 preserving e/f offsets. Source tags, TRC encoding kind, function number and sampled table drive the transform into the ICC reference sRGB D50 target; retained evidence includes Display-P3+sRGB-like type-3, non-P3 sRGB-D50+gamma2.2 type-3, type-0 gamma1.8/gamma2.2, distinct type-1/type-2/type-4 piecewise profiles, curveType identity/gamma1.8/gamma2.2/nonlinear 5-node sampled plus deterministic 1025-node sampled cases, per-channel type-0 R/G/B gamma approximately 1.8/2.0/2.2, mixed per-channel type-1/type-3/type-4, and mixed-encoding sampled-curveType/type-3/single-gamma-curveType. Sampled entries are read directly from the retained ICC profile rather than copied into a decoded table; a 320-byte 5-node versus 2360-byte 1025-node resource gate proves `operationPeak` grows by exactly the 2040-byte profile delta while transfer stays pixel-only, so the profile remains the sole cardinality-dependent color-metadata payload charge. The 1025-node formal path explicitly raises the probe's historical `maximumMetadataBytes` budget from 1024 to 4096; that narrow probe baseline rejects the profile before ICC work, while the product `DecodeLimits.coreV1` 4MiB default is unchanged. The profile stays in operation accounting while converted output transfers pixels only; grayscale/GA ICC, non-RGB ICC, LUT/MPE, per-channel TRCs containing any individually-unqualified curve, curveType zero-gamma or non-normalized/non-monotone sampled transforms, parametric profiles outside the normalized no-clipping subset, non-D50/white-mismatched/degenerate monitor profiles, implausible input media white, degenerate profiles, ICC+sBIT/HDR and out-of-gamut ICC conversion remain fail-closed. Full-range Display-P3 SDR, BT.2100 PQ and BT.2100 HLG cICP are represented as fixed raw signaling beside exact RGB/RGBA16 code values with no payload-charge widening. Display-P3 additionally has one explicit no-gamut-map `.convertToSRGB` slice for RGB/RGBA16 code values whose independently converted pixels all remain inside sRGB gamut; out-of-gamut P3 and every PQ/HLG conversion remain fail-closed. Full-range BT.2100 PQ additionally carries exact typed mDCV/cLLI static metadata as orthogonal stored-unit integers, again without pixel or payload-charge changes. The formal oracle keeps deterministic stored source, classic libpng RGBA16BE reconstruction/expansion, libpng `png_get_iCCP` profile extraction, libpng `png_get_cICP` field extraction, libpng fixed mDCV/cLLI getters, a separate W3C-rational-matrix cICP P3→XYZ→sRGB numerical oracle, an ICC-profile-tag + ICC-reference-sRGB-D50 deterministic oracle, and a LittleCMS 2.x differential observation: existing retained shared/per-channel-type0 and historical 5-node sampled cases keep their historical ≤1-code regression gate, while mixed per-channel parametric, mixed-encoding and 1025-node large-sampled cases require successful CMS execution with alpha exact and record the observed delta rather than treating it as a normative whole-domain bound; narrow/unqualified cICP, gray/GA cICP, LUT/MPE or structurally invalid matrix/TRC ICC conversion, P3/HLG static HDR metadata, PQ/HLG conversion and resizing remain fail-closed. The 8-bit path is public only as an opt-in bounded producer, not the default backend. High depth now has the similarly opt-in public `BoundedPNG16Decoder` narrow explicit-sRGB/full-resolution slice, but the wider high-depth ICC/cICP/HDR/sBIT/conversion implementation remains package-only; neither bounded producer changes the default ImageIO backend or claims general production qualification.

## Active priorities

1. The reusable `ImageCodec` v1 conformance kit is now extracted under `ConformanceKits/ImageCodec/v1`: it runs the backend in an independent temporary SwiftPM consumer, freezes versioned 2×2 PNG/JPEG/GIF/WebP/HEIF/AVIF fixture bytes behind a SHA-256 manifest, and executes 9 obligations covering the full 6,144-request finite-profile capability domain with an independent same-profile oracle that rejects false Cartesian products, descriptor/probe/decode/resource/hard-limit behavior, conditional `PreparedImageDecoding` one-shot create/consume/discard, prepared resource-authority lifetime, and progressive cancellation fencing. `Fixtures/CodecConformance` provides a production-style external package around the in-tree ImageIO backend; `Fixtures/LimitedCodecConformance` deliberately advertises only PNG/complete-frame and no prepared/progressive optional capability while reusing the public ImageIO pixel implementation. The separate `ConformanceKits/ImagePackedRGBA8/v1` closes the public 8-bit packed-value seam that `ImageCodec` cannot qualify: its bounded-PNG profile runs 6 source-bound obligations over a fixed 2×1 sRGB PNG, requiring packed-RGBA8 capability, deterministic probe, bounded phase ledger with caller-owned encoded-source composition, exact tight premultiplied pixels/transfer charge, hard DecodeLimits and a factory-enforced operation-byte budget. `Fixtures/PackedRGBA8Conformance` crosses a real SwiftPM package boundary around public `BoundedPNGDecoder`. `ConformanceKits/ImagePackedRGBA16/v1` now adds the corresponding high-depth gate: 8 obligations freeze the public straight-RGBA16LE value contract, 16-bit probe, bounded/composable ledger, exact 2×1 little-endian straight samples, request/DecodeLimits boundaries, untagged+sBIT source negatives, and hard operation-budget admission through `Fixtures/PackedRGBA16Conformance` around public `BoundedPNG16Decoder`. `ConformanceKits/ImageProgressivePackedRGB8/v1` now adds the independent progressive-JPEG packed-finalization gate: 8 obligations freeze the public tight RGB8 value, arbitrary-chunk/final-only lifecycle, non-consuming final-ready ledger, exact 23×13 / 897-byte RGB output and source-byte binding, chunk-partition invariance, DecodeLimits + ICC fail-closed behavior, cancellation fencing, and hard codec-owned budget through `Fixtures/ProgressivePackedRGB8Conformance` around public `BoundedProgressiveJPEG420Session`. 2. 3. Qualify progressive-JPEG latency, retained-byte growth, preview usefulness, and host integration on stable simulator and physical-device workloads, while advancing the package-only independent stateful decoder seam. The next codec-quality pressure is not generic IDCT accuracy: a source-bound controlled-sampling experiment holds source RGB, encoder quality and progressive mode fixed and finds ImageCraft/ImageIO vs libjpeg-turbo max/MAE deltas of gray 1/0.062, 4:4:4 3/0.110, 4:2:2 5/0.340 and 4:2:0 51/0.556 codes. This localizes the sparse large residual to h2v2/vertical chroma reconstruction; no observed value is promoted into a tolerance. That reconstruction frontier is now more sharply bounded: a 16-cell source-truth policy matrix proves a smooth-signal→real-step winner reversal (global/libjpeg wins all 12 continuous ramp/zigzag controls, while iMCU-clamp/ImageIO wins all 4 true boundary-step cells), so neither backend is a universal quality oracle. A fixed chroma-only 2× gradient-outlier rule then passes 24 held-out real-JPEG post-IDCT cells but is explicitly falsified by a phase-shifted two-row stripe. Two different full-resolution chroma truths can box-downsample to the same `[80,128,128,80]` samples while preferring opposite centered-vs-nearest reconstructions; therefore no deterministic chroma-only policy can claim universal source-truth dominance. Wider 2-D axis-only heuristics have likewise retained curved/thin-feature counterexamples. An explicit natural-image objective is now source-bound rather than merely proposed: four pinned public-domain photographs are re-encoded at the retained quality-75 4:2:0 setting, all reconstruction candidates share the same post-IDCT Y/Cb/Cr planes and integer color transform, and a preregistered 8x8 non-overlapping mean RGB-channel block-SSIM objective (RGB MAE only as tie-break) ranks global centered/fancy H+V first on all 4/4 images. Centered also has the lowest RGB MAE on every case; the v3 adaptive-vertical candidate is second in aggregate and never wins a retained source. This supports retaining centered reconstruction under this explicit objective, not universal source-truth or human-opinion superiority: the corpus is small and the source references are decoded JPEG thumbnails, while the phase-shifted ambiguity counterexample remains valid.
