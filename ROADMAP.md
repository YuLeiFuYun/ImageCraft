# ImageCraft Roadmap

ImageCraft is an actively developed pre-1.0 package. The repository contains only the current public contracts, implementation, tests, retained corpus, and reproducible evidence needed to validate them.

## Current baseline

- Independent SwiftPM products: `ImageCraftCore` and `ImageCraftImageIO`.
- iOS 15+ and macOS 12+.
- Bounded PNG/JPEG/GIF probing and static primary-frame decoding.
- Exact-timeline GIF/APNG and pre-split JPEG-sequence preparation with on-demand frames, bounded decode windows, source reuse, cancellation, strict Codable invariants, format allowlists, APNG CRC/type/order validation, GIF interactive/text-rendering rejection, early frame admission, cumulative sequence metadata budgets, actual decoded-row-stride publication checks, and owned-APNG persistent semantic replay anchors that eliminate unnecessary checkpoints only when full-canvas source/background semantics prove a safe later replay start. Full-source + previous and subrect-background remain conservative controls. These animation bytes are published in `0.1.0-alpha.7` (`3b7f7ef212acfa42a022d7cd0bfad73c0cd2d252`), which is also Fovea's exact package pin. That closes component publication, not host animation adoption: Fovea still has no production `EncodedAnimationPlaybackPreparing` implementation backed by ImageCraft, so the animation path remains integration- and device-qualification pending.
- Bounded progressive-JPEG sessions with monotone non-final generations, cancellation fencing, terminal reclaim after accepted-input failures, and a package-internal 500-SOS CPU-amplification ceiling shared by full-container security inspection and the incremental parser. A separate source-bound libjpeg-turbo 3.2.0 classic-API probe now proves that persistent buffered-image coefficient state can consume arbitrary 1-byte through full-file chunk schedules without replaying prior entropy: 5 cases / 21 schedules retain identical scan-completion state and final RGB, while private jmemmgr 3.2.0 checkpoints expose the dominant retained/final-render allocator live bytes without promoting that private ABI to a public contract. The same probe now observes virtual-barray controls before realization: four 1920-wide cases have an exact multi-minheight no-backing-store hinge (`threshold-1` fails before coefficient allocation; threshold succeeds byte-exact), while the 23×13 case intentionally falsifies a universal 1-byte rule because libjpeg's mandatory one-minheight fallback succeeds even with `max_memory_to_use=1`.
- Static PNG and JPEG encoding with explicit color, orientation, alpha, metadata, and output-byte policies.
- Versioned capability, resource, lifecycle, and failure contracts.
- Public API, external-consumer, retained-corpus, independent-oracle, platform, and performance gates.
- Reproducible direct-ImageIO vs ImageCraft raster-path comparison with alternating measurement order, raw samples, input identity, and exact pixel-output validation.
- Schema-5 target-derived raster probe records decode, creation, exact-pixel identity, byte cost, and cached-image materialization; the nearest-integer aspect-fit normalization candidate is retained as a measured negative result. Static ImageIO codec implementation version 5 replaces cross-call `CGImageSource` retention with bounded pure-value prepared state and an independent aggregate prepared-store authority.
- Independent PNG qualification now provides a real non-ImageIO raster path for static full-resolution non-interlaced grayscale 1/2/4/8-bit, grayscale+alpha8, RGB8, RGBA8 and indexed 1/2/4/8-bit sources with explicit sRGB authority, plus a separately bounded Adam7 RGBA8+sRGB slice. The 8-bit implementation is exposed through the public opt-in `BoundedPNGDecoder` packed producer with a mandatory hard operation budget and public phase ledger; the default ImageIO backend remains unchanged. It includes indexed PLTE/tRNS, grayscale/RGB tRNS, truecolor suggested PLTE, exact packed-value conformance, explicit operation-budget admission, pure RFC1950/RFC1951, one 36 KiB streaming logical-output window that covers the full 32 KiB DEFLATE lookback plus pending delivery without a second history copy, a caller-owned cross-IDAT byte cursor with no concatenated compressed-body copy, packed-row/pass-aware unfiltering with no full inflated or per-pass surface, shared immutable validated container facts, and source-bound libpng hostile/conformance evidence. Preserve-source RGB ICC is implemented behind stricter non-interlaced unit/resource gates; non-interlaced untagged input is qualified only for an explicit `.convertToSRGB` fallback while preserving `.absent` source provenance, and still fails under `.preserveSource`; Adam7 source types outside RGBA8+sRGB, unqualified cICP/HDR and other unrepresented color semantics fail closed. A separate package-only high-depth seam defines orthogonal packed-format dimensions and exact straight RGBA16LE storage; `PNGIndependentRGBA16Decoder` now covers all standard non-indexed 16-bit PNG source channel models—grayscale, grayscale+alpha, RGB and RGBA—in non-interlaced and Adam7 scan order under explicit sRGB/full-resolution qualification. Gray/RGB `tRNS` comparisons stay in the complete UInt16 stored-sample domain; GA/RGBA stored alpha remains straight. The bounded inflater feeds exact 2/4/6/8-Bpp source rows and scatters or expands directly into the final RGBA16LE value without pass surfaces. Structured `sBIT` metadata preserves the actual source channel model (`gray`, `gray+alpha`, `RGB`, or `RGBA`) without rewriting stored pixels or inventing source alpha for tRNS-derived output. RGB/RGBA16 additionally implement preserve-source embedded RGB ICC with pre-inflate admission and exact profile-byte retention; pixels remain raw source-faithful RGBA16LE and profile bytes enter transfer/resource accounting. A second ICC slice now converts a generic forward-device RGB/XYZ matrix/TRC subset whose qualified profile class is either monitor (`mntr`) or input (`scnr`): both classes require a nondegenerate authored device-to-XYZ-PCS matrix and no LUT/MPE transform; monitor profiles additionally require D50 media white within s15Fixed16 quantization tolerance and colorants that reconstruct that white, while input profiles treat `wtpt` as captured-medium metadata and require only a plausible nonnegative-X/Z, positive-Y value rather than forcing device code white to D50, and either one qualified shared RGB TRC or three per-channel independently-qualified TRCs whose curveType/parametric encodings, functions and parameters may differ. Shared TRCs may be parametric type-0...type-4 whose source-domain mapping is finite, normalized, weakly nondecreasing and needs no source clipping, or `curveType` count=0 identity, count=1 positive u8Fixed8 forward gamma, or count>1 normalized weakly-nondecreasing UInt16 samples with ICC-defined uniform-domain linear interpolation. Type-0 requires positive gamma; type-1/type-2 add positive affine scale, an in-domain threshold and normalized upper endpoint; type-3/type-4 require valid breakpoint/power-base, nonnegative lower slope, near-continuity and normalized endpoints, with type-4 preserving e/f offsets. Source tags, TRC encoding kind, function number and sampled table drive the transform into the ICC reference sRGB D50 target; retained evidence includes Display-P3+sRGB-like type-3, non-P3 sRGB-D50+gamma2.2 type-3, type-0 gamma1.8/gamma2.2, distinct type-1/type-2/type-4 piecewise profiles, curveType identity/gamma1.8/gamma2.2/nonlinear 5-node sampled plus deterministic 1025-node sampled cases, per-channel type-0 R/G/B gamma approximately 1.8/2.0/2.2, mixed per-channel type-1/type-3/type-4, and mixed-encoding sampled-curveType/type-3/single-gamma-curveType. Sampled entries are read directly from the retained ICC profile rather than copied into a decoded table; a 320-byte 5-node versus 2360-byte 1025-node resource gate proves `operationPeak` grows by exactly the 2040-byte profile delta while transfer stays pixel-only, so the profile remains the sole cardinality-dependent color-metadata payload charge. The 1025-node formal path explicitly raises the probe's historical `maximumMetadataBytes` budget from 1024 to 4096; that narrow probe baseline rejects the profile before ICC work, while the product `DecodeLimits.coreV1` 4MiB default is unchanged. The profile stays in operation accounting while converted output transfers pixels only; grayscale/GA ICC, non-RGB ICC, LUT/MPE, per-channel TRCs containing any individually-unqualified curve, curveType zero-gamma or non-normalized/non-monotone sampled transforms, parametric profiles outside the normalized no-clipping subset, non-D50/white-mismatched/degenerate monitor profiles, implausible input media white, degenerate profiles, ICC+sBIT/HDR and out-of-gamut ICC conversion remain fail-closed. Full-range Display-P3 SDR, BT.2100 PQ and BT.2100 HLG cICP are represented as fixed raw signaling beside exact RGB/RGBA16 code values with no payload-charge widening. Display-P3 additionally has one explicit no-gamut-map `.convertToSRGB` slice for RGB/RGBA16 code values whose independently converted pixels all remain inside sRGB gamut; out-of-gamut P3 and every PQ/HLG conversion remain fail-closed. Full-range BT.2100 PQ additionally carries exact typed mDCV/cLLI static metadata as orthogonal stored-unit integers, again without pixel or payload-charge changes. The formal oracle keeps deterministic stored source, classic libpng RGBA16BE reconstruction/expansion, libpng `png_get_iCCP` profile extraction, libpng `png_get_cICP` field extraction, libpng fixed mDCV/cLLI getters, a separate W3C-rational-matrix cICP P3→XYZ→sRGB numerical oracle, an ICC-profile-tag + ICC-reference-sRGB-D50 deterministic oracle, and a LittleCMS 2.x differential observation: existing retained shared/per-channel-type0 and historical 5-node sampled cases keep their historical ≤1-code regression gate, while mixed per-channel parametric, mixed-encoding and 1025-node large-sampled cases require successful CMS execution with alpha exact and record the observed delta rather than treating it as a normative whole-domain bound; narrow/unqualified cICP, gray/GA cICP, LUT/MPE or structurally invalid matrix/TRC ICC conversion, P3/HLG static HDR metadata, PQ/HLG conversion and resizing remain fail-closed. The 8-bit path is public only as an opt-in bounded producer, not the default backend; the high-depth path remains package-only and not production-qualified.

## Active priorities

1. Extract a reusable codec conformance kit with versioned fixtures and observation schemas.
2. Continue the phase-aware resource ledger now wired into progressive, prepared ImageIO, animation qualification, and the narrow independent PNG path: stable-device qualify bounded paths and close framework-private ImageIO `operationPeak` with real allocator/workspace authority. Host total-live-set composition now has a backend-neutral phase operation: `ImageDecodeResourceLedgerSnapshot.coexistenceBound(for:callerRetainedBytes:)` adds caller-owned encoded source or previously published payloads to any codec phase without reassigning ownership, preserves structured unknown reasons, and saturates rather than wrapping; the older branch-output helper delegates to the same operation-peak composition. Progressive JPEG now distinguishes retryable pre-acceptance encoded-byte admission from fatal post-acceptance parser/capability/finalization failures: the latter terminalize immediately, reclaim retained input, fence late calls, reject known trailing bytes as soon as EOI makes them impossible to legitimize, and reject scan-count CPU amplification before further ImageIO work. The independent libjpeg-turbo mechanism gives the first concrete alternative state model: at 1920×1285 4:2:0, coefficient payload is 7,464,960 B, pinned 3.2.0 jmemmgr reaches 7,549,477 B at EOI, and the probe-owned source manager brings retained decoder live bytes to 7,680,677 B; final RGB coexistence raises the observed modeled live bytes to 15,082,277 B. For the same case, the pre-realize pool is 84,009 B and the exact full-virtual-array availability hinge is 7,548,969 B; one byte less fails before coefficient payload allocation, while the successful start pool reaches 7,549,134 B, proving `max_memory_to_use` is not a whole-pool cap. The 23×13 one-minheight counterexample succeeds even with a configured value of 1 B. The old “derive the 84,009-byte workspace” frontier is now closed for the qualified pinned domain: a 12-width × 4-sampling edge matrix derives every upsampler/main-controller `alloc_sarray`, applies the source allocator's row alignment/header/chunk rules, then adds coefficient-array allocation; all 48 cases exactly reproduce the post-start pool, and 5 retained held-out cases do the same without fitted residual. These are still pinned allocator observations, not a cross-version or RSS promise. The narrow independent progressive JFIF 4:2:0 path now has both one-shot and real incremental owned-state authority. The one-shot decoder admits raw RGB + its geometry-derived aligned coefficient/control/reconstruction arena before payload allocation and validates unsupported JPEG ICC without profile reassembly. The independent incremental-session evidence has now advanced through **v17** without rewriting history. Transport remains syntax-derived at **414 B**, but actual ownership no longer confuses future authority with live state: an empty session retains only 414 B transport while pre-SOF table maximum authority is 2,432 B; present DQT slots transfer ownership through SOF2 and are released at first SOS; Huffman retained bytes track only current table payload while 2,176 B remains the future maximum; padded Y MCU syntax no longer forces dummy coefficients into persistent planes; bound quantization is UInt8 across scans and widens only in render scratch; progression is packed into **96 B four-bit state**. Render lifetime is also increasingly exact: validated EOI compacts final-ready state to RGB only, v15 removed the deferred Y boundary row, and v16 fuses centered H2V2/box chroma reconstruction directly into integer YCbCr→RGB so two full-width reconstructed Cb/Cr staging rows disappear. The v16 row-state formula is **16×yRowStride + 18×chromaRowStride**; versus v15, render scratch falls exactly `2×yRowStride` with persistent/max-retained authority unchanged. v17 then changes the final-only EOI coexistence rather than shrinking preview scratch further: once EOI/progression/trailing-byte validation is complete, it releases the transport backing, materializes **tight 4:2:0 Y/Cb/Cr samples** with only **384 B = 64×Int32 IDCT workspace + 64×UInt16 quantization widening** scratch, returns only after releasing coefficient/Huffman/control state, and allocates RGB afterward. Thus final-only peak is `max(transition, entropy rollback, Huffman mutation, persistent+samples+384, samples+RGB)` instead of persistent+RGB+RenderArena. The tiny every-scan control remains **7,743 B**; 576×576 final-only falls **2,009,022→1,495,840 B** with 497,664 B tight samples; restart64 falls **30,142→21,280 B** with 6,144 B samples. Schema17 compares corresponding v16 reports and requires persistent/max-retained/final RGB identity, a strict final-only peak reduction, and unchanged every-scan peak; the 576×576 frozen RGB SHA remains `5b1738e18c84104586fbe59f37348d8bf1fd9af2cd7036874f156625549bafbb`. Canonical scan progression is now an explicit semantic authority too: a second Ah=0 first scan over an established coefficient fails closed even though permissive libjpeg-turbo accepts that redundant stream. Further JPEG coefficient-lifetime compression now has diminishing whole-session benefit relative to the representation boundary. The first half of that boundary is now closed package-internally: `ProgressiveImagePackedRGB8FinalizingSession` exposes a backend-neutral `ImagePackedRGB8 + sourceByteCount` finalization without Core Graphics, with source-bound evidence fixing tight RGB8/no-alpha layout, `.sRGB` output fallback versus `.absent` source profile, prefinish transfer-ledger equality, no second Data payload backing and terminal reclaim. That seam now also has a package-only `DecodedImage` materializer. Packed-finalization v2 first established an exact 24-bit RGB `CGImage` over one explicit malloc-owned provider copy and deliberately recorded **897 B packed + 897 B provider = 1,794 B known pixel-payload coexistence** while leaving total materialization `operationPeak` **unknown(frameworkPrivateOperationAllocation)**. v3 then falsifies the need for that copy: `CGDataProvider(data: packed.data as CFData)` retains the standard packed backing itself on the qualified runtime, provider and packed byte pointers are identical, the provider remains valid after packed/session scope ends, and known pixel-payload coexistence falls exactly **1,794→897 B** with unchanged provider hash, 24-bit geometry, transfer charge and source-profile facts. Crucially the wrapper `operationPeak` remains framework-private unknown. The independent JPEG implementation remains package-only and default ImageIO decode pixels/rollout are unchanged. PNG security/decode already share one immutable validated chunk/range plan. Tight packed RGBA plus independent PNG proves one end-to-end bounded operation/transfer slice with caller-owned input separated from codec-owned charge; it does not prove ImageIO transient allocation.
3. Qualify progressive-JPEG latency, retained-byte growth, preview usefulness, and host integration on stable simulator and physical-device workloads, while advancing the package-only independent stateful decoder seam. The next codec-quality pressure is not generic IDCT accuracy: a source-bound controlled-sampling experiment holds source RGB, encoder quality and progressive mode fixed and finds ImageCraft/ImageIO vs libjpeg-turbo max/MAE deltas of gray 1/0.062, 4:4:4 3/0.110, 4:2:2 5/0.340 and 4:2:0 51/0.556 codes. This localizes the sparse large residual to h2v2/vertical chroma reconstruction; no observed value is promoted into a tolerance. That reconstruction frontier is now more sharply bounded: a 16-cell source-truth policy matrix proves a smooth-signal→real-step winner reversal (global/libjpeg wins all 12 continuous ramp/zigzag controls, while iMCU-clamp/ImageIO wins all 4 true boundary-step cells), so neither backend is a universal quality oracle. A fixed chroma-only 2× gradient-outlier rule then passes 24 held-out real-JPEG post-IDCT cells but is explicitly falsified by a phase-shifted two-row stripe. Two different full-resolution chroma truths can box-downsample to the same `[80,128,128,80]` samples while preferring opposite centered-vs-nearest reconstructions; therefore no deterministic chroma-only policy can claim universal source-truth dominance. Wider 2-D axis-only heuristics have likewise retained curved/thin-feature counterexamples. The next quality mechanism must either add independent information/prior (for example luma-guided structure with its own counterexamples) or adopt an explicit perceptual/natural-image objective; do not tune a larger chroma neighborhood and relabel it as source-truth authority. Before an independent JPEG backend can move beyond research, close that explicitly scoped quality policy, broaden the owned incremental 4:2:0 session beyond its current JFIF/table/transport slice using the same phase-lifetime authority, preserve the public packed/resource representation seam, and preserve the existing final representation/color/lifecycle contracts.

5. Qualify animated-image playback scheduling, bounded frame-cache admission, Fovea HTTP integration, MJPEG multipart framing, and competitor A/B evidence before enabling a default UI path.

7. Keep ImageIO as the conservative reference backend while admitting additional codecs through the same finite contract and conformance gates. The package-only independent PNG slice proves the packed/resource mechanism on a growing lossless domain. Current host evidence separates synthetic and actual-stream behavior: repetitive/incompressible and RGB fixtures are already competitive with or faster than Apple/ImageIO, while one deterministic high-entropy RGBA fixture retains a DEFLATE-core gap. Profiling localized that gap to fast-literal/match processing rather than generic PNG row/premultiply cost; a same-table three-literal reservoir unroll is retained because A/B improved the actual stream, while larger tables, wide refill, scalar short-match copies, SIMD Adler/premultiply and forced cursor inlining were measured negative and removed. Continue with actual-IDAT and physical-device evidence rather than speculative micro-optimization. Lossy JPEG qualification still must keep representation conformance separate from reconstruction-quality authority, and the old T68 pixel gate is not widened post hoc.

Gray/RGB `tRNS` uses complete UInt16 matching; GA/RGBA stored alpha stays straight; `sBIT` records the actual source channel model and remains metadata-only. Preserve-source RGB ICC has a no-transform raw-sample + external `png_get_iCCP` oracle and phase-aware profile retention/admission contract. ## Release policy

- `main` may contain breaking changes before 1.0.
- Every published development tag is immutable.
- Stable claims require clean-clone CI, public API review, current integration gates, and evidence bound to the exact source identity.
- Capability gaps and non-comparable results remain explicit; no global “best codec” claim is permitted.
